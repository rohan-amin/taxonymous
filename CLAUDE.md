# Taxonymous

Open-source tool that scrubs sensitive information from tax documents (1099s, W-2s, etc.) locally, so they can be uploaded to Claude for review without exposing identity.

## Decisions so far (2026-10-16)

- **License:** AGPL-3.0 (lets us use PyMuPDF for true redaction).
- **Inputs:** mix of downloaded PDFs (text layer) and scans/photos, so local OCR (Tesseract) is in v1.
- **v1 scope:** redaction + verification only. No network calls, no Anthropic API. The user reviews output, then manually uploads files from `ready-to-upload/` into the Claude desktop app.
- **Outputs per document:** truly redacted PDF (text/pixels removed, metadata/annotations/form fields stripped) + placeholder text (`<SSN_A>`, `<ACCT_1>`). Only the PDF is exported to `ready-to-upload/` (user's choice, 2026-10-19), named with the user's details replaced by their kind (`Fidelity NAME Trust 1099.redacted.pdf`); the .txt stays in `work/` for verification and the UI. Placeholder→real mapping ("vault") is stored in a separate folder that is never uploaded.
- **Redact identifiers, not amounts:** SSN/ITIN/EIN, account/routing numbers, names, addresses, DOB. Dollar amounts and box numbers stay.
- **Redact only what you list (default since 2026-10-19, user's choice):** the values in Your details (names, SSNs incl. masked/last-4 forms, DOB, addresses, phones, emails, listed accounts/EINs/cards; an account's routing number and its last 4 wherever they stand alone; "Other numbers" such as e-file PINs and client IDs; the tax preparer's name, firm, address, phone, PTIN and EIN; each person's occupation and employer and each address's school district; an address's city and ZIP on their own, and its state next to the ZIP; all added 2026-10-20 at the user's choice) plus anything SSN-shaped. Nothing else: an employer's name and EIN stay readable. Verification checks only those, and documents don't affect each other. Review catches misses; "Add to my details" on the review screen adds one and re-runs. The guessing detectors (labels, long numbers, IDs, organizations, the spaCy name model, other documents' values) caused cascading false failures on real documents and were removed entirely on 2026-10-20 (user's choice), with their option, tests and dependencies. The test corpus's answer key (`tools/fixtures/manifest.py`) expects other people's details to stay readable, except their SSNs.
- **Barcodes are blacked out, whatever they hold (2026-10-20, user's choice):** a state return's 2D barcode carries the whole return. Found by decoding each rendered page (zxing-cpp, `src/taxonymous/barcode.py`); pixels, drawn bars and barcode-font characters are removed. Verification fails a page with a barcode that still reads.
- **Verification is mandatory:** re-extract text and OCR the redacted output; fail if any known value or pattern survives.
- **Architecture:** Python core engine (no UI code) → local FastAPI server bound to 127.0.0.1 → React + TypeScript web UI with side-by-side original/redacted review. Designed so a native Mac app later wraps the same UI (pywebview/Tauri) without a rewrite.
- **Desktop app = native shell + web view (2026-11-12, user's choice after trying the slice):** not SwiftUI. The Mac app wraps the same React UI (pywebview today; Tauri is the option if native menus/shortcuts matter more), with "feels like a Mac app" details required: system font, compact controls, real menu bar, no title bar (transparent over the page, window buttons in a toolbar band with native How It Works / My Profile buttons, no in-app brand; 2026-11-12, user's choice), file picker, drag-in, dark mode, no white flash, remembered window. Product copy says "AI" (never Claude) and "your computer" (never "this Mac"; "your", not "this", since 2026-11-15).
- **New UI direction (2026-11-12, from the prototype artifact):** three panels: files (left drawer), document (middle: fixed header with status, Next document, tools; scrolling viewer), My profile (right drawer); both drawers drag-resizable and hideable. Clicking a value adds it to My profile (all documents); a drawn box is this document only, shown striped blue while reviewing. Welcome screen with 5 steps and the "stays on this computer" promise. Errors are plain language, written in the UI (`ui/src/workspace/messages.ts`), not server strings. Lives in `ui/src/workspace/` behind `?ui=workspace`; the classic screen is still the default until it covers everything.
- **Two OCR engines on Mac (2026-11-12, user's choice: "correctness is more important than speed but the app can't be slow"):** Tesseract and macOS Vision misread differently (Tesseract read a receipt's card "1111" as "4444" in both redaction and verification, so a leak passed; Vision drops digits in crowded table cells). Redaction reads scans/pictures with both (union); verification reads every output page with Vision and image pages with Tesseract too; text-layer pages get Vision only (the text layer is the other reader). Vision runs in helper processes (`python -m taxonymous.vision --serve`; Vision serializes requests within a process). `TAXONYMOUS_OCR=tesseract` turns Vision off; without pyobjc (Windows/Linux) it is Tesseract only. A Swift helper (`native/macos/vision_ocr.swift`) is the packaging plan; it doesn't build until the Command Line Tools are reinstalled (compiler/SDK mismatch).
- **Speed scales with the machine, never assumes a fast one (2026-11-12):** documents run in lanes (`src/taxonymous/lanes.py`): 1 below 8 cores (in-process, as before), 2 from 8, 3 from 12, at most one per 4 GB; each lane is a helper process (`python -m taxonymous.lanes --serve`, PyMuPDF is not thread-safe) and the cores' OCR slots are shared out. The vault is shared across processes by file lock (each writes back only its own changes). All outputs are written atomically (`src/taxonymous/files.py`): the UI polls them while the worker writes. Text pages with pictures OCR only the pictures. Overrides: `TAXONYMOUS_LANES`, `TAXONYMOUS_WORKERS` (OCR reads at a time). Tests run one lane (conftest).
- **Click a value (2026-11-12):** in the workspace, "Click a value" offers every word on the original page not already removed (`src/taxonymous/words.py`: text layer after the same bake+sanitize as redaction, read once per document; OCR for scans, photos and pictures on text pages, one page at a time; in memory only, never written). One click grows to the whole value on its row (name across a form's boxes, street, "City, ST ZIP", phone with its area code); shift-click extends. `src/taxonymous/suggest.py` says what it is from its shape and the nearest label (rules only, no ML) and cautions on amounts, companies, someone else's EIN and masked SSNs. Adding re-runs that document first, then every cleaned one (all of them when it created the profile). A person can be the first detail added, as "You".
- **UI review pass (2026-11-12, from outside feedback, user's go-ahead):** no absolute safety claims: a passed document says "Checked: none of your details were found", with what was removed by kind and "What was checked" built only from the report (`engines` per page, `pictures`), plus the caveat that only My profile and SSN shapes are removed. Fit width is the default zoom (capped at 200%), Fit page, trackpad pinch / ⌘-scroll zoom. "Remove more" mode selector (Click a value · Draw a box). When every document has passed, "Save safe copies…" is the primary action (review sheet, Save N, Show in Finder via `POST /api/reveal`). My profile shows a short summary (full list on request) and starts hidden on windows under 1280px. Welcome steps follow "tell it once → removed everywhere → review → checked again → share".
- **Second UI pass (2026-11-13, outside feedback, user's go-ahead):** states are Needs review → Checked → Saved everywhere; "safe copy" is the file, not a state. The status is one line, what was done then how it was verified ("Cleaned: 7 details removed · Checked again: none left"; user's choice 2026-11-14), the rest under "What was checked". Two header rows (status + Next/Save; modes, then Original/Safe copy, Fit, zoom); mode hints and Apply/Undo/Done in a bar over the document. One finish action: "Save N safe copies…" (review sheet), then "N saved · Show in Finder". My profile entries are clickable: where each was removed (`GET /api/profile/found`, from the vault's placeholder→key and each document's boxes; a person's SSN/DOB/job/employer count as that person; unlisted SSN-shaped numbers are no one's), and the document outlines those boxes. Placeholder labels stay (the AI needs `<NAME_A>` vs `<NAME_B>`; hiding them would be hidden text), drawn in quiet grey, with a legend line saying what they are.
- **Labels are the AI's view of who's who (2026-11-13):** a person's letter is the same in every kind: the profile's person n is `<NAME_X>` and `<SSN_X>` with X its nth letter, whoever is seen first; anyone not in the profile (unlisted SSN shapes, preparers) gets letters after the profile's people; names already handed out never change (vault.py `_new_name`, `vault.people` set by redaction). Two people's findings are never merged into one label: a surname-first name must stay on one line unless a comma says so, and when two people's findings overlap, the one crossing a line break is cut there, only if coverage is unchanged (detect.py `_split`). `tests/test_labels.py` checks merging, splitting, letters, and scans sharing labels with their text versions.
- **Keep the workspace uncluttered (2026-11-14, user's choice):** one control per action. No Next document button (the documents list does that; ⌘] and the Go menu remain). Saving has one home: the document header's button once everything is checked ("Save N safe copies…", then "N saved · Show in Finder"); the documents list has only Add documents and the filter, plus a progress line while documents are being cleaned (counts are in the group headings; the summary opens from the header button or File › Safe Copies…); the summary has one button. Toolbar: How It Works, My Profile, Document Review.
- **Removing a document (2026-11-14, user's choice):** right-click › Remove from Taxonymous…, or Delete on the selected document, then a confirmation that leads with "Your original file isn't touched." `DELETE /api/documents/{id}` removes the inbox copy, its work outputs, the reviewer's boxes and its saved safe copy (any name it was saved under), and folders left empty; 409 while it is being cleaned. The vault keeps its placeholders (shared with other documents; a value keeps its label if it comes back).
- **Quitting mid-clean (2026-11-14):** a lane that loses the app stops at once without writing anything (its progress write used to fail inside verification, which recorded the document as an error: "This file couldn't be opened"). The app (`create_app(resume=True)`, native window only) cleans again on open every document without a report or with an error report (`api.unfinished`).
- **Permanent entry ids (2026-11-14, user's choice):** every profile entry (person, address, account, EIN, card, number, preparer) carries an `id` made when it's added (`e` + 8 hex) and kept through edits and reordering; vault keys are `kind:<id>` (`person:e3fa91c2b`, `routing:<account id>`), phones and emails by value (`phone:5555550188`). A person's letter comes from their id (`vault.letters`); a removed entry's letter is retired. Older profiles get each entry's position as its id on first load (`Workspace.upgrade`, `profile.with_ids`), which is what the vault used, so labels don't change; old `phone:N`/`email:N` vault keys are rekeyed by value. Ids never leave the computer: documents show only the letters.
- **Role labels (2026-11-14, user's choice: one role per person, switch everything):** a person's label is their role, each detail under it: `<TAXPAYER>`, `<TAXPAYER_SSN>`, `<SPOUSE_DOB>`, `<DEPENDENT_2>`, `<SUCCESSOR_TRUSTEE_1_SSN>`; preparers `<PREPARER_1>`, `<PREPARER_1_PTIN>`; an SSN not in the profile `<UNKNOWN_SSN_1>`; a family surname alone `<SURNAME_1>`; everything else numbered (`<ACCT_1>`). Roles: taxpayer, spouse (one each), dependent, grantor, trustee, successor trustee, beneficiary, executor, decedent, other (`PERSON_n`). The vault keeps each person's base by permanent id (`bases`) and every base given up (`retired`), so a number is never given to someone else; a role change relabels that person (`Vault.relabel`, run by `Workspace.upgrade`, which also switched older vaults' letter labels). Saving the profile cleans every cleaned document again; the app does the same on open after a relabel. This replaces the A/B letter scheme of 2026-11-13.
- **Account and address labels; the state stays readable (2026-11-14, user's choice):** an account has a type (checking, savings, CD, brokerage, traditional/Roth/SEP IRA, 401(k), Roth 401(k), pension, HSA, 529, Coverdell, mortgage, student loan, loan) and an owner (a person in the profile by id, joint, trust, estate): `<TAXPAYER_ROTH_IRA_1>`, `<JOINT_CHECKING_1>` (+`_ROUTING`), `<DEPENDENT_1_529_1>`; an address a type: `<HOME_ADDR>` (one home), `<PRIOR_HOME_1_ADDR>`, `<RENTAL_1_ADDR>`, `<VACATION_HOME_1_ADDR>`, `<BUSINESS_1_ADDR>`; unset stays numbered (`<ACCT_n>`, `<ADDR_n>`), and clearing a type goes back to a number. An address's state is now left readable by default (profile `keep_state`, a checkbox at the top of the profile editor turns it off): the street, city and ZIP are still removed. This replaces "its state next to the ZIP" from 2026-10-20.
- **The browser is the product; the Mac app is paused (2026-11-14, user's choice after the spike):** the whole app runs in a web page (`web/`): the workspace UI over the app's own server code (`taxonymous.api`, unchanged but for `create_app(worker=...)`) in Pyodide, a home engine answering the UI's `/api/` requests (handed over by the service worker) and cleaning lanes as workers; OCR is Tesseract + PaddleOCR (WebGPU when there is one), barcodes zxing-wasm. Profile and vault live in an encrypted Taxonymous file you open and save; documents only in the page. The Mac app (pywebview over the same UI and server) keeps working but isn't being developed. `web/README.md`.
- **Hosted on Cloudflare Pages (2026-11-15, user's go-ahead):** `https://taxonymous.pages.dev`: the landing page at the root (`web/landing/`: what it does, labels vs black bars, one return at a time, prompts to use with the safe copies; says Beta and "source available", never free), the app at `/app/` (its own service worker scope and `taxonymous-app-*` caches; `web/landing/sw.js` clears an install from before the move). The landing page's copy runs ahead of the app (guided setup, trust/estate returns, speed estimate, required passphrase: mockup at https://claude.ai/artifact/MJLwcZDfA9s7DRsKw6S5GG). a classic Pages project `taxonymous` in the user's Cloudflare account (not Workers; the account's other project is unrelated). Deploy with `npx wrangler pages deploy web/dist --project-name taxonymous --branch main` after `web/build.py`; push the deployed commit first, since the start screen's AGPL source link points at the public repo. Cloudflare sees only requests for the app's files; leave Web Analytics off.
- **Progress (2026-11-12):** one bar per document that only grows (stages weighted; a second look fills what is left; full only when done), with time left from its own pace, and the batch's time left from measured seconds per page.
- **Tooling:** Python with `uv`; React/TS (Vite) frontend.
- **Document-agnostic:** engine scrubs PII from any document with generic matching; no per-form layouts or special cases. Test corpus: W-2, 1099 family (incl. 1099-G), brokerage consolidated statements, K-1s (+ attached statements), draft Schedule H, IRA statements/5498, DAF documentation, receipts.
- **GitHub:** `git@github.com:rohan-amin/taxonymous.git` via single-repo SSH deploy key (`~/.ssh/taxonymous_deploy`, set in repo-local `core.sshCommand`). No `gh` CLI auth. Don't push without asking.
- **Build plan:** `docs/PLAN.md`.
- **Location:** stays in Dropbox. Dependency folders (`.venv`, `node_modules`) should be excluded from Dropbox sync.

## Commands

- `uv run pytest` / `uv run ruff check .`; `uv run pytest -m slow` adds the 150-page timing test and the whole corpus in one workspace
- `tools/fixtures/odd.py` builds odd PDFs (hidden text, broken fonts, rotation, encryption...) for `tests/test_odd_pdfs.py`; `src/taxonymous/sanitize.py` is what makes a PDF hold only what its pages show
- `uv run python -m tools.fixtures.generate` builds the fake corpus into `tests/fixtures/generated/` (gitignored); `manifest.json` there is the ground truth (`redact` / `keep` per document).
- `uv run taxonymous init|run --workspace DIR` (inbox → work → verify → ready-to-upload); `redact` and `verify` for single files. Takes PDFs (text, scanned, mixed) and photos.
- `inbox/` may have folders (added 2026-11-07, user's choice; e.g. one per tax year): a document's id is its path as an output stem (`2024/w2`), `work/`, `ready-to-upload/` and `vault/overrides/` mirror the folders, and API routes take ids with slashes (`{stem:path}`; the bare document GET is registered last).
- `uv run taxonymous merge --workspace DIR [FOLDER] [--max-mb N]` (and Merge on a folder in the UI, added 2026-11-07, user's choice) joins a folder's passed documents into one PDF (or parts, never splitting a document) with a contents page of public names; no bookmarks (an outline is off-page text, refused by verification). The merged file is verified again (profile, SSN shapes, barcodes; each document's kept/shown values allowed on its pages) and goes to ready-to-upload only if every part passes. `src/taxonymous/merge.py`; last result in `work/<folder>/.merge.json`.
- `uv run taxonymous explain --workspace DIR DOC [PLACEHOLDER]` prints why a document failed, or (with e.g. `ID_10`) why one box is there, with every value masked (letters a/A, digits #, form words kept); the user can paste its output without sharing their data
- `uv run python -m tools.viewer_diff ORIGINAL.pdf REDACTED.pdf [PAGE]` shows, per font, which text macOS (Preview) leaves out that MuPDF (the review UI) draws; prints font names and counts only
- `uv run python -m tools.pdf_shape FILE.pdf [FILE.pdf ...]` (or `--ops PAGE`) shows how a PDF is built (saves, catalog, per-page text drawing), or how one page places its text, with every string masked; for comparing an original with its redacted copy
- `uv run --with pywebview python -m tools.native_window --workspace DIR [--dev] [--classic]` opens the UI in a native window (the new workspace by default; `--dev` loads Vite on :5173 with the API on :8765 for live edits); menu bar actions run Python and only send the page a command name
- `uv run python web/build.py` builds the browser app into `web/dist` (the UI too; pinned downloads cached in `web/.downloads`); `uv run python web/serve.py [PORT]` serves it on 127.0.0.1:8800.
- `uv run taxonymous serve --workspace DIR` runs the review UI + local API (127.0.0.1 only, token required); endpoints are listed in `src/taxonymous/api.py`.
- UI: `cd ui && npm install && npm run build` (React/TS/Vite, output `ui/dist`). `tests/test_ui.py` (Playwright, system Chrome) needs the build and is skipped without it. If `~/.npm` is not writable, pass `--cache` to npm.
- Pre-commit PII guard: `git config core.hooksPath .githooks` (runs `tools/check_pii.py`).

## Rules

- Never commit real tax documents or `profile.json`. `.gitignore` blocks all PDFs/images except `tests/fixtures/`; don't weaken it.
- Never place real tax documents in this repo. Use synthetic fixtures only (IRS blank forms filled with fake data).
